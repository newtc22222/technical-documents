# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## What this repo is

A Docusaurus 3.10 static documentation site (TypeScript config, React 19). It is content-first: almost all work happens in `docs/` and `i18n/vi/`, not in `src/` (which is still the classic-template homepage). Published to GitHub Pages (`newtc22222/technical-documents`, `gh-pages` branch).

`README.md` is **not** a project readme — it is the English twin of `docs/_notes/i18n.md`, a Docusaurus i18n walkthrough.

## Commands

```bash
npm start                      # dev server, English (defaultLocale)
npm start -- --locale vi       # dev server, Vietnamese (one locale at a time in dev)
npm run build                  # builds BOTH locales -> build/ (en) and build/vi/
npm run serve                  # http-server ./build --single (must build first)
npm run typecheck              # tsc (config-only; no emit)
npm run clear                  # wipe .docusaurus cache when the dev server acts stale
npm run write-translations -- --locale vi   # regenerate/merge i18n JSON message files
npm run deploy                 # docusaurus deploy to gh-pages (needs GIT_USER)
```

There are no tests and no linter. `npm run build` is the real gate: `onBrokenLinks: "throw"` means any dead internal link fails the build.

Two dev-server caveats: the local search index is produced at build time, so search only works via `build` + `serve`; and the locale dropdown can't switch locales in dev — restart with `--locale vi`.

## Content architecture

Four independent doc trees under `docs/`, each wired in **three** places — add all three when introducing a new tree:

| `docs/` dir | sidebar id in `sidebars.ts` | navbar label in `docusaurus.config.ts` |
| --- | --- | --- |
| `ff-restaurent/` | `ffRestaurent` | FF RESTaurent |
| `laptech/` | `laptech` | Laptech |
| `lingu-flow/` | `linguFlow` | LinguFlow |
| `guides/` | `knowledge` | Guides |

All four sidebars are `autogenerated`, so structure comes from the filesystem plus:

- `_category_.json` per folder — `label`, `position`, `collapsed`, and optional `link: {type: "generated-index"}`. A generated-index category produces a route derived from its label (e.g. `Building App` → `/docs/category/building-app/`), and `src/pages/index.tsx` links to exactly that. Renaming a category label breaks that link and the build throws.
- Frontmatter. `ff-restaurent/**`, `laptech/**` and `lingu-flow/**` use full frontmatter (`id`, `title`, `sidebar_label`, `sidebar_position`, `description`); `guides/**` files have **no** frontmatter and rely on their H1 plus `_category_.json`, so their order within a category is alphabetical by filename.

`trailingSlash: true` — write internal links with a trailing slash.

### Underscore prefix = excluded from the build

Docusaurus drops `_`-prefixed files and directories from routing. This repo uses that deliberately:

- `docs/_notes/` — authoring notes, never published
- `docs/_assets/` — images, referenced from docs by relative path (`../../_assets/foo.jpg`) and still bundled
- `docs/laptech/_private/`, `docs/laptech/_private/_design.md` — drafts

Renaming one of these without the underscore publishes it.

## i18n

`defaultLocale: "en"`, locales `["en", "vi"]`. English is the source: `docs/`, `src/pages/`. Vietnamese overrides mirror it file-for-file:

```
i18n/vi/docusaurus-plugin-content-docs/current/**   # translated docs (mirrors docs/)
i18n/vi/docusaurus-theme-classic/{navbar,footer}.json
i18n/vi/docusaurus-plugin-content-docs/current.json # sidebar category labels
i18n/vi/code.json                                   # <Translate> strings from src/
```

The homepage (`src/pages/index.tsx`) is one component for both locales: its strings go through `<Translate>`/`translate()` with `homepage.*` ids, so run `write-translations` after changing them and fill the new keys in `code.json`. Its section links are hard-coded to the first doc of each category; the build fails if one goes stale.

A missing Vietnamese file silently falls back to English. Today `guides/` is fully translated, `laptech/` has only `_private/`, and `ff-restaurent/` and `lingu-flow/` have no vi files. Because docs reference images by relative path, `_assets/` is duplicated inside the vi tree too; keep it in sync when adding images.

Known drift: `current.json` still holds 8 orphaned `sidebar.tutorialSidebar.*` keys from before the sidebars were renamed; they resolve nowhere and can be deleted. `write-translations -- --locale vi` merges into existing files rather than overwriting translated messages.

## Markdown features available

- Mermaid via `@docusaurus/theme-mermaid` + `markdown.mermaid: true` — use ` ```mermaid ` fences.
- Syntax highlighting is limited to Prism defaults plus `bash, docker, java, markdown, mermaid, sql, yaml` (`themeConfig.prism.additionalLanguages`). Other languages render unhighlighted until added there.

## Syncing FF RESTaurent docs from the wiki

`docs/ff-restaurent/` mirrors the private `ff-restaurent` GitHub wiki. The sync is one-way (wiki to docs), and `scripts/sync-ff-wiki.mjs` does it, driven by `scripts/ff-wiki-sync.config.json`.

```bash
# Clone or pull the wiki first: git clone https://github.com/newtc22222/ff-restaurent.wiki.git
npm run sync:ff-wiki -- --wiki ../ff-restaurent.wiki --pages Release-v2.4.0   # sync named pages
npm run sync:ff-wiki -- --wiki ../ff-restaurent.wiki --check                 # list pages that differ, write nothing
npm run build                                                                # broken links fail the build
```

- `FF_WIKI_DIR` can replace `--wiki`.
- Pages matching `exclude` (`_Sidebar`, `_Footer`, `Pre-release-Checklist-*`) are never published, and links to them become plain text. Keep internal checklists out of this public site.
- `Home` is marked `manual`, so `docs/ff-restaurent/index.md` is edited by hand. Add new releases to its Releases table and update its "Current state" note yourself.
- A new wiki page needs a `pages` entry with `path` and `frontMatter` (at least `id`, `title`, `sidebar_label`, `sidebar_position`). Existing pages keep their front matter.
- The script converts GitHub alerts to admonitions, rewrites wiki links to relative `./page.md` links, strips HTML comments, and labels bare code fences `text`. It does not re-apply table alignment or other hand edits, so prefer `--pages` over a full sync and review the diff.

## Conventions and known config quirks

- `AGENTS.md` is this same guide for non-Claude agents (Codex, Gemini CLI, Cursor). Apply every edit to both files; only the title and intro line differ.
- Commits follow Conventional Commits (`feat:`, `fix:`, `docs:`, `chore:`), the convention documented in `docs/guides/version-control/commit-code.md`; git history matches it.
- The classic preset enables the blog, but there is no `blog/` directory. Every build prints `Warn: blogDir doesn't exist` and emits an empty `/blog` route — expected, not a regression.
- `docusaurus.config.ts` has `url: "https://github.com"` with `baseUrl: "/"`, which does not match a GitHub Pages project site (`https://newtc22222.github.io` + `/technical-documents/`). Fix both before relying on `npm run deploy`.
- `@docusaurus/faster` is installed but not enabled (`future.experimental_faster` is unset); only `future.v4` is on.
- No CI workflow exists in the repo — deploys are manual.
