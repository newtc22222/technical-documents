# 🚀 Cách tổ chức tài liệu **nhiều dự án** trong Docusaurus sao cho hiệu quả

Docusaurus support khá tốt cho multi-project docs, nhưng để nó thực sự “đi vào vận hành”, bạn cần chọn đúng mô hình tổ chức. Dưới đây là setup chuẩn industry, dễ maintain, dễ scale cho cả team lớn.

---

## 🧭 **1. Chọn kiến trúc tài liệu phù hợp**

Bạn có 2 mô hình quen thuộc:

---

### **Mô hình A — Mỗi dự án là một “doc section” chính trong site**

> *(Đơn giản – phù hợp khi mỗi dự án không quá lớn)*

```txt
docs/
  project-a/
    intro.md
    guides/
    api/
  project-b/
    intro.md
    setup/
    architecture/
  project-c/
    ...
```

Sidebar cho từng dự án được cấu hình riêng trong `sidebars.js`:

```js
module.exports = {
  projectA: [{ type: 'autogenerated', dirName: 'project-a' }],
  projectB: [{ type: 'autogenerated', dirName: 'project-b' }],
  projectC: [{ type: 'autogenerated', dirName: 'project-c' }],
};
```

👉 Ưu điểm

* Dễ setup, phù hợp team nhỏ
* Các dự án nằm gọn cùng một site docs
* Dễ cross-linking giữa docs

👉 Nhược điểm

* Nếu dự án lớn → sẽ phình sidebar

---

### **Mô hình B — Mỗi dự án là một “Versioned docs plugin riêng”**

> *(Chuyên nghiệp – dành cho team lớn hoặc multi-product)*

Trong `docusaurus.config.js`:

```js
plugins: [
  [
    '@docusaurus/plugin-content-docs',
    {
      id: 'project-a',
      path: 'project-a',
      routeBasePath: 'project-a',
      sidebarPath: require.resolve('./sidebars/projectA.js'),
    },
  ],
  [
    '@docusaurus/plugin-content-docs',
    {
      id: 'project-b',
      path: 'project-b',
      routeBasePath: 'project-b',
      sidebarPath: require.resolve('./sidebars/projectB.js'),
    },
  ]
];
```

👉 Từng dự án có:

* Tài liệu riêng
* Sidebar riêng
* URL riêng
* Có thể versioning độc lập

👉 Ưu điểm

* Scale cực tốt
* Kiểu tổ chức y hệt documentation của dạng enterprise (AWS/GCP style)

👉 Nhược điểm

* Setup phức tạp hơn một chút
* Mỗi dự án cần 1 plugin config riêng

---

## 📚 **2. Chuẩn hoá cấu trúc tài liệu cho từng dự án**

Bạn nên giữ **một chuẩn thống nhất** cho toàn bộ docs, ví dụ:

```txt
project-x/
  ├─ intro.md
  ├─ overview/
  │    ├─ architecture.md
  │    └─ tech-stack.md
  ├─ setup/
  │    ├─ requirements.md
  │    └─ installation.md
  ├─ guides/
  │    ├─ usage.md
  │    ├─ workflows.md
  ├─ api/
  │    ├─ rest.md
  │    └─ schema.md
  ├─ infra/
  └─ troubleshooting/
```

👉 Khi mọi dự án dùng chung layout, người đọc sẽ “feel like home” ở bất kỳ docs nào.

---

## 🧩 **3. Tận dụng frontmatter để phân loại rõ ràng**

Ví dụ:

```md
---
id: architecture
title: System Architecture
sidebar_position: 2
tags: [architecture, design]
---
```

Lợi ích:

* Sidebar rõ ràng
* Dễ search theo tag
* Dễ build dashboard documentation (nếu bạn cần)

---

## 🎨 **4. Tạo trang Landing riêng cho từng dự án**

Ví dụ URL:

```txt
/project-a
/project-b
/project-c
```

Trang landing nên có:

* Tóm tắt dự án
* Sơ đồ tổng quan (mermaid hoặc image)
* Link nhanh đến các mục quan trọng
* Trạng thái project / owner team / contact

---

## 📝 **5. Quản lý phiên bản (Versioning)**

Dành cho dự án có release cycle:

```bash
yarn docusaurus docs:version project-a 1.0
```

→ Mỗi dự án có thể version độc lập.

---

## 🔍 **6. Search hiệu quả cho multi-project**

Bạn nên bật:

* Algolia DocSearch (nếu public)
* Local search plugin (nếu private)

Nếu multi-project, nhớ cấu hình để search index không bị trộn quá mức.

---

## 🔧 **7. Quy định quy trình viết tài liệu (cho team)**

Để tránh tài liệu bị loạn sau vài tháng:

* Quy định mỗi MR phải cập nhật docs tương ứng
* Template PR bắt buộc checklist docs
* Chọn một “doc owner” cho mỗi project
* Sử dụng Lint Markdown (`remark-lint`)

---

## 🚦 **8. Khi nào nên tách Front-end, Back-end, DevOps, Infra?**

✔ Nếu dự án lớn → **tách thành folder bên trong project**
✔ Nếu dự án nhỏ → **gộp chung dưới mục “Architecture / Tech Breakdown”**

Ví dụ (chuẩn nhất):

```txt
project-a/
  architecture/
    frontend.md
    backend.md
    database.md
    infra.md
    devops.md
```

---

## 🎯 **Tóm lại: Setup tối ưu cho multi-project Docusaurus**

* Dùng **multi-docs plugin** nếu nhiều dự án và muốn quản lý chuyên nghiệp
* Dùng **1 thư mục + phân nhánh dự án** nếu đơn giản hơn
* Tạo **structure chuẩn** cho tất cả dự án
* Tách FE/BE/Infra khi dự án lớn
* Thêm landing pages, versioning, search, linting để docs dễ dùng và dễ maintain

---

Nếu bạn muốn, mình có thể giúp bạn:
✨ thiết kế **cấu trúc thư mục hoàn chỉnh** cho hệ thống nhiều dự án của bạn,
✨ hoặc tạo luôn file `docusaurus.config.js` + `sidebars.js` tối ưu.

Chỉ cần nói bạn đang có bao nhiêu dự án và chúng thuộc loại nào (FE/BE/Infra…).
